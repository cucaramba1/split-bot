# HANDOFF: Split Bot

Обновлено: 2026-11-04 (пачка 2). Этот файл каждая новая сессия читает первым делом.

## Что это

Общий Telegram-бот Некита, Антона и Полины: голосом или текстом заносим общие траты в донгах, делим на троих или на пару, в воскресенье итог с минимумом переводов. Плюс очереди «байк» и «вода» вне денег.

- Спека (одобрена): `docs/specs/2026-11-04-split-bot-design.md`
- План (одобрен, режим Native): `docs/plans/2026-11-04-split-bot.md`. Интерфейсы, тесты и значения там.
- Голос через Groq API, не локальный Whisper (решение 04.11 после разбора сторожа, правило в `~/Claude Code/CLAUDE.md`).

## Как выполнять

- Скилл `superpowers:executing-plans`, задачи строго по порядку, TDD как в плане, `- [x]` в плане по мере шагов.
- Git: `git init` в Task 1, коммит после каждой задачи.
- Код плана не проходит тесты → `superpowers:systematic-debugging`, чинить минимально, отличие записать ниже в «Отклонения».
- В конце пачки: `uv run pytest -q` зелёный → обновить этот файл → сказать Некиту промпт для следующего чата.
- После Task 7 один свежий ревьюер на Opus по всему коду (так выбран Native).

## Отклонения от плана

- Task 2 (переделано 04.11 по решению Некита): план давал `offsets_for_next`, но с ним цикл Антон → Полина → Некит невозможен. Теперь `next_turn(counts, last)`: ничья решается по давности последнего хода, потом NAMES. Вместо `offsets_for_next` есть `queues.equalize_offsets` и `db.seed_queue(queue, order)` / `db.queue_last(queue)` (стартовая история пишется в turns без черновика). В Task 6 `queue_set` и `queue_status` вызывают `next_turn(db.queue_counts(q), db.queue_last(q))`.
- Task 4: в `parser.parse` параметр `s` keyword-only (в плане после аргумента с дефолтом, это синтаксическая ошибка). Тестов 25 вместо 23 (+ псевдоним «Никита», + неизвестная очередь). Корень «к» в `should_parse` только отдельным словом (`\bк\b`), иначе ловит «шашлык».
- Task 1: коммит-трейлер `Co-Authored-By: Claude Sonnet 5.5` (модель сессии), а не Opus 5.5 из плана.

## Ревью Opus (после Task 7) и фиксы

Исправлено одним проходом (каждое: тест RED→GREEN, сьют 65/65): отмена ошибочного «оплачено» (`db.unmark_paid`, `Service.unpaid`, кнопка «↩️ Не оплачено»); `asyncio.Lock` вокруг `parse_fn` (один `claude -p` за раз, иначе пробивает лимит сторожа); `setup.sh install` делает `enable` перед `bootstrap` (повторный install иначе мог упасть).

Отложенные minor (решает Некит):
- Кривой `callback_data` (`ok:abc`, `qn:bike`) роняет хэндлер без `c.answer()`; повторный тап в `qs`/`qn` даёт «message is not modified».
- Посторонний получает алерт «Это не твоя трата» вместо молчания.
- `/undo` после `/queue_set` может сбить очередь (undo хода, засчитанного до seed).
- Пустой разбор (`kind=expenses`, пусто, без вопроса) даёт пустую карточку с «Записать».
- Старые кнопки «оплачено» умирают, если `/balance` пересчитал сумму; частичной оплаты нет.
- Итог недели уйдёт сразу при первом запуске (last_report пуст), возможен дубль при сетевой ошибке после доставки.
- `should_parse` ловит «иду к Антону», «в 7»; `True` проходит как сумма 1; текст ошибки голоса короче, чем в спеке.
